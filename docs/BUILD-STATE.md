## What we're building

A rebuilt **TaskMaster** — a weight-based task-management SaaS (removes decision fatigue by auto-prioritizing tasks; "What's Next?"). Self-hosted on the owner's **k3s** cluster via **ArgoCD** (GitOps), images pushed to Docker Hub namespace **`magmakomer`** (`magmakomer/taskmaster-backend`, `magmakomer/taskmaster-frontend`). Multi-user SaaS with free/premium tiers + virtual economy. Local-first testing now; public domain + TLS added later.

Full product vision: `docs/prd.md`. Full technical spec: `docs/technical-specification.md`.

- **Secrets:** Sealed Secrets for k8s (later).

## Environment / gotchas (learned the hard way)

- **OS:** Windows, bash shell (MINGW). **MINGW truncates multi-statement command output and aborts scripts on a non-zero mid-pipe.** Run one command per call, or write output to a `/tmp` file and `cat` it. Avoid `set -e` multi-step curl scripts. **Heredocs are also unreliable here: even a quoted-delimiter heredoc (`<<'EOF'`) gets scrambled/interleaved mid-stream on long content with backticks/`??`/`>=` — DO NOT write files via heredoc. Reliable file writes: use the editor's write/edit tools, OR append one line per `printf '%s\n' '...single-quoted...'` call (escape literal `'` as `'\''`), OR use a `python3 - <<'PY'` script for metacharacter-free blocks (JSON etc.). `tasks.md` was corrupted twice by heredocs before switching to per-line printf.**
- **`pg` returns DATE and TIMESTAMPTZ columns as JS `Date` objects, not strings.** Normalize (e.g. `normalizeDate`/`normalizeTime` in taskService) before calling `.split()` etc. This caused a real bug.
- **`express-rate-limit` keeps a timer that hangs Jest.** The auth limiter is skipped when `NODE_ENV=test` (`skip: () => process.env.NODE_ENV === 'test'`).
- **node-pg-migrate v7 needs `ts-node`** (installed) — NOT tsx — to run `.ts` migrations. The migrate scripts pass flags: `-m src/database/migrations -j ts --tsconfig tsconfig.json --envPath .env` (or `.env.test`).
- **`npm test`** uses `cross-env NODE_ENV=test`. Jest globalSetup runs migrations on the test DB; setupAfterEnv truncates tables between tests and loads `.env.test`.
- Migrations use timestamp-style names starting `1000000000000`.
- **`pg` parses a DATE column into a JS `Date` at the SERVER-LOCAL midnight of the stored calendar day** (not UTC midnight). So to recover the stored 'YYYY-MM-DD' you MUST use LOCAL getters (getFullYear/getMonth/getDate), NOT UTC getters — UTC getters shift the date back a day whenever the server runs ahead of UTC (BST/CEST). This bit `streakRepository.normalizeDate` (fixed). Contrast: `zonedNow` in userTime builds a Date from Intl wall-clock parts, so its `getTime()` is NOT the true instant — never use `zonedNow` for elapsed-time/age math.
- **Weight age must clamp at 0.** `ageInDays = Math.max(0, Math.floor((now - createdAt)/DAY))`. A just-created task can have `created_at` (DB `now()` at insert) a few ms AHEAD of the later-captured `now`, and `Math.floor` of a tiny negative → -1 → base `(ageInDays+1)*mult = 0`, zeroing the whole weight. Surfaced only under full-suite load; clamped in `weight.ts`.
- **Timezone is per-user, stored in `users.settings` JSONB under `timezone` (IANA name, default 'UTC').** Server "today"/"now" for weight/defer/streaks must be computed in the user's zone via `src/services/time/userTime.ts` — never server-local. All age/due-proximity math uses the TRUE instant; only calendar-day comparisons (`localToday`) use the zoned date.

- `1000000000003_completion_support`: `tasks.weight_at_completion integer` (nullable), `tasks.repeat_series_id uuid` (nullable) + partial index. `repeat_series_id` is a **standalone fresh UUID per repeatable series** (NOT a task id), set in `create` via `CASE WHEN $repeatable THEN gen_random_uuid() ELSE NULL END`.

Daily streak = `series_id IS NULL`; per-series = `series_id = repeat_series_id`. Reversible down restores `task_id`.
- `1000000000005_default_project`: added `projects.is_default boolean NOT NULL DEFAULT false`; relaxed the priority_order CHECK (`projects_priority_order_check`) from 1-20 to **0-20** so the per-user **Unassigned** project sits at `priority_order = 0`; partial unique index `uq_projects_one_default ON projects (user_id) WHERE is_default` (exactly one per user). ### task-recurrence (`.kiro/specs/task-recurrence/`) — DONE & verified
Order-independent completion listener that regenerates a repeatable task on completion: inserts one active Next_Occurrence sharing the SAME `repeat_series_id` with copied subject/priority/projects/due_time/repeat_pattern and a freshly-computed `due_date`. NO new migration (the occurrence is an ordinary `tasks` row).
Pure `src/services/tasks/recurrence.ts`: `addDays(date,n)` + `weekdayOf(date)` (DST-safe UTC-noon, mirrors `nextCalendarDate`) and `nextDueDate(pattern, anchor): string|null` — daily = anchor + max(1,interval); weekly + non-empty days_of_week = earliest listed weekday strictly after anchor (scan k=1..7); weekly + empty/unset days_of_week = anchor + 7*max(1,interval); end_date guard returns null when next > end_date (YYYY-MM-DD string compare). Out-of-range weekday numbers never match (no throw).
Confirmed decisions: DD-1 schedule-anchored (anchor = completed occurrence `due_date` when non-null, else user local completion day via `localCalendarDate(resolveTimezone(user.settings.timezone))`); DD-2 weekly w/o days_of_week advances 7*interval days; DD-3 due_time carries over unchanged.
`recurrenceService.onTaskCompleted(event)`: returns early for non-repeatable / null pattern / null series id; resolves anchor (skips the DB lookup when due_date present; normalizes due_date via LOCAL getters per the pg-DATE gotcha); `nextDueDate` null → schedule ended → no insert; else `taskRepo.createOccurrence({...})`. Order-independent (reads only event.task + timezone), registered LAST in registerAllListeners; dispatcher isolates throws so completion never fails.
New repo fn `taskRepository.createOccurrence(occ: NewOccurrence)` — mirrors `create` but takes an EXPLICIT `repeat_series_id` (never gen_random_uuid()), sets is_repeatable=true, leaves completed_at/archived_at/weight_at_completion at null defaults, reuses `insertAssociations` for project links. (Kept separate from `create`, which mints a fresh series id.)
Files: services/tasks/recurrence.ts, services/tasks/recurrenceService.ts, edits to repositories/taskRepository.ts (NewOccurrence + createOccurrence) + registerListeners.ts (listener last, order-independent). Tests: services/tasks/recurrence.property.test.ts (P1-P4 pure, fast-check >=100 runs), routes/recurrence.test.ts (11 integration incl. non-UTC anchor fallback, end_date stop+boundary, series-continues, single-insert, dispatcher isolation w/ registry restore). 157 tests / 23 suites green.
